# River Raid Port

The playable page runs a port of the River Raid ROM's own game logic. The previous JS/Python reimplementation was moved to `archive_old_port/`.

## Run

```powershell
npm run serve
```

Open:

- Playable port: http://127.0.0.1:8080/
- Inspector: http://127.0.0.1:8080/inspector.html (still uses the older `riverraidVisiblePort.mjs` model)

## How the port works

Game state is the ROM's zero page: a 256-byte array where every variable lives at its ROM address.

- `riverraidRiver.mjs`: the block generator (`.setBlockVars`) ported instruction for instruction, plus models of what the kernel draws on each of its 160 lines (playfield, enemy sprites, jet, missile) and of its per-block hardware collision checks.
- `riverraidStatus.mjs`: the score, fuel gauge, lives and copyright display, modelled on the ROM's status kernel.
- `riverraidFrame.mjs`: the rest of the frame (MainLoop setup, enemy movement, joystick, fuel, crashes, scoring, missile, sound registers, switches, Reset/GameInit/LooseJet/SwapPlayers), ported instruction for instruction.
- `riverraidPlayfieldData.mjs`, `riverraidKernelSprites.mjs`: ROM tables and shapes, generated by `tools/gen-playfield.mjs` and `tools/gen-kernel-sprites.mjs`.
- `game.mjs`: input (joystick bits, fire, RESET switch) and drawing of the kernel output with TIA priority and Stella's NTSC palette.
- `tiaSound.worklet.js`: a TIA sound generator (after Ron Fries' TIASound) that plays the AUDC/AUDF/AUDV values the ROM's sound routine writes each frame. Sound starts on the first key press (browser autoplay rules); M mutes.

## Check

```powershell
npm run check
```

Syntax-checks the modules and runs `smoke-check.mjs`. That includes a power-on/RESET run of the ROM port, which compares a checksum of the start screen; that screen matches a Stella snapshot pixel for pixel.

## Verify against the ROM

```powershell
npm run verify
```

Needs the ROM at `reference/river-raid-wiz-main/baserom.a26` (MD5 `393948436d1f4cc3192410bb918f9724`). The ROM is not committed. `tools/atari/` holds a dev-only 6502 core and a minimal VCS bus that run the real ROM as an oracle. The `tools/verify-*.mjs` scripts compare the port with it:

- `verify-blockgen`: the block generator, state by state
- `verify-kernel-pf`: per-pixel playfield, playfield and background colors on all 160 lines
- `verify-kernel-objects`: jet, enemy sprites and colors, and missile, per line
- `verify-collisions`: collision results per block
- `verify-frame`: whole frames, with crashes, refuels, hits, game overs and restarts, including the sound register writes
- `verify-status`: the status display against a pixel render of the ROM's TIA writes (`tools/atari/tia-render.mjs`)

The whole picture, playfield and status display, matches a Stella snapshot pixel for pixel. The oracle's own TIA renderer places status-area objects 6 pixels left of Stella, so `verify-status` compares content with that offset and absolute positions come from Stella.

## Known gaps

- The sound generator's polynomial noise follows TIASound's structure, but the exact LFSR phases have not been compared with Stella's audio.
- The oracle's collisions use the same object geometry as the port. That geometry is calibrated against Stella snapshots, and missile placement follows TIA timing.
